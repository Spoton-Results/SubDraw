# Overview

SubTracker is a subcontract management platform designed for the construction industry. It enables General Contractors (GCs) to create projects, invite subcontractors, manage bids, track change orders, and process invoices. Subcontractors can submit bids, propose change orders, and submit invoices. The platform aims to streamline the subcontracting workflow, enhance financial transparency, and improve project management for both GCs and subcontractors.

## System Architecture

The project is built as a pnpm monorepo using Node.js 24 and TypeScript 5.9. The backend is an Express 5 API server, and the frontend is a React + Vite application utilizing Tailwind CSS, React Query, React Hook Form, and shadcn/ui. PostgreSQL with Drizzle ORM is used for data persistence, with Zod for schema validation. API client code is generated from an OpenAPI specification using Orval.

**Key Architectural Decisions:**

-   **Monorepo Structure:** Organizes API server, frontend, and shared libraries (API spec, generated clients, database schema) for cohesive development.
-   **Authentication:** Cookie-based JWT authentication with bcryptjs for password hashing. Includes robust middleware for role-based access control (`requireAuth`, `requireGC`, `requireSub`, `requireGCOwner`). Features permanent sessions and password change session invalidation.
-   **Subcontractor Data Isolation:** Ensures strict data privacy for subcontractors, preventing them from viewing other subs' information or project details not relevant to their scope.
-   **Financial Tracking:** Implements comprehensive financial features including bid management, subcontract creation, change order processing, and invoice management with auto-flagging for over-budget invoices and a GC override mechanism.
-   **Retention Tracking:** Integrates a detailed retention framework, calculating retention amounts, displaying retention balances on a scoreboard, and supporting retention-release invoices.
-   **Bank Draw Schedule:** A GC-only feature allowing GCs to manage project budgets by defining cost categories, tracking committed amounts against budgets, and linking subcontracts to specific line items.
-   **Notification System:** Uses SendGrid for various email notifications triggered by key actions within the platform (e.g., bid awards, change order status changes, invoice submissions).
-   **UI/UX:** Uses Tailwind CSS for styling and shadcn/ui for components, ensuring a modern and consistent design. The frontend routes are structured for clear navigation between dashboards, project details, subcontract details, and administrative sections like contact management and team management.
-   **Demo System:** Includes a fully functional demo environment with seeded data that resets daily, allowing users to explore the platform's capabilities without registration.
-   **Free Trial:** Offers a 14-day free trial for GCs, providing full access to features before requiring a subscription.
-   **Action Required Dashboard:** A consolidated action panel at the top of the GC dashboard aggregating all items needing attention across every active project — flagged invoices, pending approvals, disputed payments, past-due invoices, unsigned subcontracts, and expiring insurance. Groups items by urgency (URGENT/PENDING/UPCOMING) with direct clickable links to each item. Shows a zero-state green banner when all is clear.
-   **Payment Terms & Due Dates:** Configurable Net 15/30/45 payment terms per subcontract (GC-only pill-button selector). Approved invoices automatically get a `paymentDueDate` computed as `approvedAt + paymentTermsDays`. Due dates are displayed inline in the invoice list with color-coded urgency (gray >14d, amber ≤14d, orange ≤7d, red overdue). Sub-facing 7-day and overdue reminder banners appear on approved invoices nearing or past due. PDF invoices display dynamic "Net X" and "Due [date]" in both the INVOICE DETAILS section and the Amount Due box.
-   **Plan File Download Tracking:** Every plan file download by a sub is recorded in the `plan_file_views` table (timestamp, sub name, company). GC sees per-file "Viewed by X subs" expandable list with names and timestamps. Sub sees green checkmarks on downloaded files and a plan review status panel in the bid form. Bid cards on the GC view show "Plans Reviewed" / "X/Y Plans Downloaded" / "No Plans Downloaded" badges. Submitting a bid without downloading any plan files triggers a warning dialog. Downloads by subs with existing subcontracts are also logged to the subcontract activity log.
-   **Percentage Complete on Invoices:** Subs must report what percentage of their total scope of work is complete when submitting each invoice (required field, 1–100). This is stored on each invoice as `percentageComplete`. GC sees: (1) a "Scope Complete" row in the Financial Scoreboard showing the latest invoice's %; (2) a "Scope Complete" progress bar in the Invoice Progress card; (3) a percentage badge on each invoice card; (4) regression warnings (amber banner) if a sub reports a lower % than their previous invoice; (5) inconsistency flags (orange banner) if the claimed % differs from the financially-invoiced % of contract value by more than 20 points. PDF invoices include "Scope Complete: N%" in the INVOICE DETAILS section. Activity log updated to include the percentage.
-   **Contact Book Bulk Import:** GC can import subcontractors into the contact book via CSV upload or manual one-at-a-time entry. The "Import Contacts" button in the Contact Book header opens a modal with two tabs: "Upload CSV" shows how-it-works instructions, a downloadable CSV template (Company Name, Contact Name, Email, Phone, Trade Specialty, License Number), and a drag-and-drop file upload zone; after upload, a preview table shows all valid rows (invalid rows highlighted with error reasons) before a confirm button triggers the bulk import. "Add Manually" tab shows a form to add a single contact with the same fields. The API creates sub user accounts for new emails (or finds existing accounts) and upserts sub profiles (trade, phone, license). Duplicate detection: contacts already in the book are skipped and counted separately. Success banner shows "X contacts imported successfully" plus a count of duplicates skipped. A `contact_name` column was added to `gc_contacts` to store the individual point-of-contact name (separate from the company name). Contact cards in the list now show the contact name below the company name with a person icon.
-   **Additional Insurance Requirements:** GC can specify detailed insurance requirements beyond standard GL and WC coverage on each subcontract's Insurance Certificate card. A preset checkbox grid (Umbrella Policy, Performance Bond, Payment Bond, Professional Liability, Automobile Liability, Builder's Risk) auto-populates a free-text textarea where GC can type any custom requirements (one per line). The additional requirements text is saved to the `additional_requirements` column on `subcontract_insurances`. The insurance display card shows the requirements as a bullet list, visible to both GC and sub. The "Compliance & Insurance Requirements" card (previously "Compliance Checklist") on the subcontract detail shows a blue "Required Insurance Coverage" panel at the top that combines GL minimum, WC minimum, and all additional requirements — giving subs a single place to see all insurance they need to provide. The insurance card display logic was fixed to show coverage data when a record exists regardless of whether an expiration date is set.
-   **Contractor License Tracking:** GC can record and track contractor license details per subcontract: license number, type, issuing state, and expiration date. Stored in `contractor_licenses` table (one-to-one with subcontracts). License status (VALID / EXPIRING_SOON ≤30d / EXPIRED / NO_LICENSE) shown as a color-coded badge in the subcontract header (blue=valid, yellow=expiring, red=expired). A "Contractor License" card below the Insurance card shows all details with an "Add License / Update" button for GC. Shows sub's self-entered license number from their profile with a match/mismatch indicator for verification. License column (xl breakpoint) added to the project detail subcontract table. A `licenseNotifier.ts` sends GC email alerts at 30-day and 7-day intervals before expiration. Invoice PDFs include the contractor license number in the FROM section if recorded. Activity logged as LICENSE_UPDATED.
-   **Subcontract Agreement Document Upload:** Replaced the electronic-signature-only system with a full document upload workflow. GC uploads their own subcontract agreement (PDF or Word) via the "Subcontract Agreement" card on the subcontract detail page. Upon upload the sub is notified by email that their agreement is ready. The sub downloads it, signs it physically or digitally, and uploads the signed copy back. The GC is notified by email when the signed copy is received. Both documents (original + signed) are stored permanently in object storage. Status badge dynamically shows: NO DOCUMENT / PENDING SUB SIGNATURE / SIGNED & UPLOADED / WAIVED. GC can waive the signature requirement per-subcontract (and reinstate it). GC can delete either document. A yellow banner appears on the sub's view when their signature is pending. Activity log updated with new types: CONTRACT_UPLOADED, CONTRACT_SIGNED, CONTRACT_REMOVED, CONTRACT_WAIVED, CONTRACT_UNWAIVED. Action Required dashboard shows awaiting-signature items only when GC has uploaded a doc and sub hasn't returned a signed copy. DB: 7 new columns on `subcontractsTable` (contractDocPath, contractDocName, contractDocUploadedAt, signedContractPath, signedContractName, signedContractUploadedAt, contractWaived).
-   **Multi-file Plan Upload & Scope Documents:** Plan files section supports selecting multiple files at once (no description required — file name used as label). File size stored in DB and displayed in the list alongside upload date. A separate "Scope of Work Documents" card directly below Site Plans allows GC to upload specifications, requirements, and scope docs (same multi-file upload, same format support). Both sections visible to invited subs; scope docs also appear inline in the sub's bid form for quick reference. Delete buttons for GC on both sections. Backend: `fileSize` column added to `planFilesTable`; new `scopeDocumentsTable` and `scope-documents.ts` API route (GET/POST/DELETE at `/projects/:projectId/scope-documents`).
-   **Compliance Checklist:** A project-level compliance system that allows GCs to define required tasks and documents that each subcontractor must complete before they can submit invoices. GC creates checklist items on the project detail page (between Scope Documents and Active Subcontracts sections) with a title, required/optional flag, and optional "allow document upload" setting. Required items block invoice submission for subs until marked complete. The compliance card on the subcontract detail page shows all items per-sub with "Mark Done" / "Undo" buttons (both GC and sub can mark complete; sub needs GC approval to unmark). Items that allow document upload show an "Upload Doc" button for subs to attach supporting files (stored in object storage). The project detail subcontracts table shows a "Compliance" column with COMPLIANT/BLOCKED/INCOMPLETE badges. The project detail Compliance Checklist card also shows a per-subcontractor summary table at the bottom. Sub dashboard shows a "Compliance Required" section listing all pending required items grouped by project, with direct links to the subcontract detail. DB: `compliance_checklist_items` table (id, projectId, title, description, required, allowDocumentUpload, sortOrder) and `compliance_completions` table (id, checklistItemId, subcontractId, isComplete, completedByRole, completedByName, completedAt, documentPath, documentName, notes). API: full CRUD at `/projects/:projectId/compliance-items`, summary at `/projects/:projectId/compliance-items/summary`, per-subcontract status at `/projects/:projectId/compliance-items/subcontract/:subcontractId`, document upload at `/projects/:projectId/compliance-items/:itemId/document/:subcontractId`, and sub-facing pending items at `/subcontracts/compliance-pending`.
-   **Comment Thread (Messages):** A per-subcontract messaging system allowing GCs and subs to communicate directly within the subcontract context. Stored in `subcontract_comments` table (id, subcontractId, userId, companyName, role, message, createdAt). Read-tracking stored in `subcontract_comment_reads` table with a unique index on (subcontractId, userId). A "Messages" card above the Activity Log in subcontract-detail.tsx shows a chat-style interface: sender's messages right-aligned in primary color, other party's messages left-aligned in muted color, each with company name, role badge (GC/SUB), and relative timestamp. Textarea + Send button (or Ctrl+Enter shortcut). Auto-scrolls to latest message; re-fetches every 30 seconds; marks as read on page mount and after receiving new messages. On new comment, an email notification is sent to the other party via `sendCommentNotificationEmail`. Unread counts are injected into the project-detail subcontract list: when a party has unread messages from the other side, a blue `MessageSquare` badge appears next to the subcontractor name in the project-detail subcontracts table. API: GET/POST `/:subcontractId/comments`, POST `/:subcontractId/comments/mark-read`.
