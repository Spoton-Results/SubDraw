Important: Do not remove, replace, or modify any existing features or functionality that is currently working. Only add the Submittals feature as described below. Keep all existing scoreboard calculation, invoice flagging, payment confirmation, change orders, and all other features exactly as they are.
Add a Submittals section to the subcontract detail page visible during CONSTRUCTION phase. A submittal is a document the GC sends to a specific subcontractor for review, response, and acknowledgment. Both the GC and sub can upload documents and send messages back and forth within each submittal thread. Everything is permanently stored and timestamped.
GC CREATES A SUBMITTAL:
On the subcontract detail page add a Submittals section with an Upload Submittal button visible to the GC only. When tapped the GC sees a form with these fields: Submittal name — required — such as Cabinet Color Selection or Approved Electrical Panel Spec. Document upload — required — accepts PDF and image files. Opening message to sub — optional — text field where GC explains what they need the sub to review and respond with. Required response date — optional — date picker. When GC taps Send to Sub the submittal is created with status PENDING REVIEW and the sub receives an email notification saying GC company name sent you a new submittal called submittal name on project name — tap here to review and respond.
SUBMITTAL DETAIL PAGE:
Each submittal opens to its own dedicated detail page showing the submittal name at the top, the current status badge, the required response date if set, and the full conversation thread below. At the top of the thread show the GC's original document with a Download button, the uploader name, and the upload timestamp.
CONVERSATION THREAD WITH DOCUMENT UPLOADS:
The conversation thread works like a messaging thread where both GC and sub can send messages and upload documents at any point in the conversation. Each entry in the thread shows the sender name and role — GC or Sub — the message text if any, any uploaded document with a Download button and the document name, and the exact timestamp. Both parties can upload documents at any point in the thread. For example the sub uploads their own product sheet or material sample in response to the GC's request. Each uploaded document shows inline in the thread with a Download button, the uploader name, and the timestamp. Messages and documents appear in chronological order oldest at top newest at bottom. Both parties are emailed immediately when a new message or document is posted. The thread is permanent and cannot be deleted by either party.
REAL WORLD EXAMPLE OF HOW THIS WORKS:
GC creates submittal called Cabinet Color Selection and uploads a spec sheet with opening message: Please review and submit your proposed cabinet color for approval before ordering. Sub receives email, opens the submittal, downloads the GC document, uploads their own product sheet showing Coffee Brown cabinets, and types: We are proposing Coffee Brown from the manufacturer standard line — see attached product sheet — please confirm approval so we can place the order. GC receives notification, reviews Coffee Brown, and replies: Coffee Brown is approved — proceed with ordering. Sub types: Understood — will place order this week — and taps Acknowledge Receipt. The submittal is permanently marked as ACKNOWLEDGED with a timestamp.
ACKNOWLEDGE RECEIPT:
At the bottom of the conversation thread the sub sees an Acknowledge Receipt button. When tapped the sub can add a final acknowledgment message and tap Confirm Acknowledgment. This sets the submittal status to ACKNOWLEDGED with a permanent timestamp showing the sub's name and the exact date and time. After acknowledgment both parties can still view the thread and add follow up messages but the acknowledgment timestamp is locked permanently and can never be changed or deleted by anyone.
SUBMITTAL STATUSES:
PENDING REVIEW in yellow — GC sent submittal but sub has not yet responded.
IN DISCUSSION in blue — messages have been exchanged but sub has not yet formally acknowledged.
ACKNOWLEDGED in green — sub has formally confirmed receipt with permanent timestamp.
OVERDUE in red — required response date has passed without acknowledgment.
GC SUBMITTAL LIST VIEW:
On the subcontract detail page the Submittals section shows all submittals in a list with submittal name, sent date, status badge, last message preview, last activity timestamp, and a View Thread button. GC can filter by status — All, Pending Review, In Discussion, Acknowledged, Overdue. Overdue submittals appear automatically in the GC Action Required dashboard showing the submittal name, sub name, project name, and how many days overdue.
SUB SUBMITTAL LIST VIEW:
On the sub dashboard add a Submittals section showing all submittals sent to them across all projects and subcontracts. Each submittal shows the document name, project name, GC company name, opening message preview, status badge, required response date if set, and a View and Respond button. New unread submittals show a blue NEW badge. Submittals requiring acknowledgment show a yellow ACTION REQUIRED badge.
DOCUMENT HANDLING:
Every document uploaded by either party is stored permanently and downloadable by both parties at any time including after the project is archived. Documents are never deleted. Each document in the thread shows the file name, who uploaded it, the date and time uploaded, and a Download button.
NOTIFICATIONS:
Sub notified by email when GC creates a new submittal. GC notified by email when sub replies with a message or document. GC notified when sub formally acknowledges. Both parties notified when any new message or document is added to a thread they are part of. GC notified when a submittal becomes overdue. All notification emails include the submittal name, project name, a preview of the latest message, and a direct link to the submittal thread.
ACTIVITY LOG:
Every action recorded permanently in the subcontract activity log with user name and timestamp. Log entries include: Submittal created and sent to sub by GC name. Message sent by GC name on submittal name. Document uploaded by sub name on submittal name. Message sent by sub name on submittal name. Submittal acknowledged by sub name on submittal name with timestamp.
IMPORTANT RULES:
Both GC and sub can upload documents at any point in the conversation thread — not just at the start. The sub's uploaded documents are their response submittals. Every document from both sides is permanently stored and downloadable forever. The acknowledgment timestamp is permanent and locked — it can never be edited or deleted by anyone including the admin. Submittals are visible only to the GC and the specific sub assigned to that submittal — other subs on the project never see it.
